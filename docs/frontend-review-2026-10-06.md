# 프론트엔드 평가 및 개선 — 2026-10-06

frontend-harness의 files 평가와 improve 패치 절차로 현재 Vite 앱을 검사했다. 허용한 소스는 `src/App.tsx`, `src/styles.css`이며, 설정·이미지·trace·응답은 프로젝트와 원본 하네스 저장소 밖에 보관했다.

## 확인된 문제와 변경

- 작게 표시되던 본문·검색·상태 레이블을 확대했다. 본문은 14px, 보조 텍스트는 12px, 모바일 입력은 16px로 조정했다.
- 태블릿에서 br이 숨겨지며 소개 문구의 단어가 붙던 문제를 공백 유지로 수정했다.
- 데스크톱 목록의 상태와 액션을 두 행으로 분리하고 액션 열을 확보해 버튼 문구가 꺾이지 않도록 했다.
- 모바일 카드와 701~1000px 카드 보기는 한 열로 표시한다. 작은 사이드바의 Private 배지는 다음 줄로 배치해 이름의 중간 끊김을 줄였다.
- 모바일 검색·분야 선택을 각각 한 행에 배치하고 버튼의 조작 영역을 확대했다.

글자와 조작 영역 확대에 따라 목록의 세로 길이는 늘어난다. 기존 색상·카드 구성·기능은 유지했다.

## 평가 범위와 결과

각 PNG를 실제로 열고 접근성 요약·기능 단언·문서 너비를 함께 평가했다. 점수는 여섯 기준의 정수 1~10점 평가 평균이며 객관적인 접근성 인증 점수가 아니다. 합격선 8과 시나리오는 실행 중 변경하지 않았다.

| CSS viewport | 대표 검사 | 개선 전 → 후 평균 |
| --- | --- | --- |
| 360×800 | 검색 결과·빈 상태 복구, 다크 목록 저장, 상세 프롬프트 편집 | 7.67 → 8.00 |
| 768×1024 | 위와 동일 | 7.54 → 8.00 |
| 1440×900 | 위와 동일 | 7.58 → 8.00 |
| 430×932 | 중간 폭 카드, 즐겨찾기 추가 후 reload 지속성 | 7.33 → 8.00 |
| 1024×768 | 위와 동일, 사이드바 줄바꿈 | 7.83 → 8.00 |

기본 실행은 12개 관찰·105개 필수 검사, 추가 실행은 2개 관찰·28개 필수 검사다. 두 실행 모두 terminal `passed`, 실패 0개다. 검사 수에는 단계 단언과 네트워크·콘솔·가로 넘침 검사가 포함되며 독립 기능 133개를 의미하지 않는다. 마지막 추가 패치는 430px 카드 열과 1024px 사이드바 줄바꿈에 해당하며 기본 3개 viewport의 결과 배치는 바꾸지 않는다.

초기 설정의 부분 문구 단언은 하네스의 전체 문자열 비교 계약과 맞지 않아 전체 기대 문구로 수정하고 새 실행을 시작했다. 그 초기 실행은 제품 결함·완료 결과에 포함하지 않았다.

기존 `npm test` 18개와 `npm run build`도 통과했다. 배포 카탈로그나 원본 스킬은 갱신하지 않았다.

## 한계

- `screen-coverage.json`은 scenarios-only이며 전체 화면 커버리지는 완료하지 않았다. 상세는 Writing Plans를 대표로 검사했다.
- 실제 터치·Safari·낮은 가로 화면·모든 상세·메뉴 키보드 포커스·클립보드 권한·Vercel 인증·외부 GitHub API는 미검증이다.
- 전체 페이지 PNG의 고정 요소는 스크롤 시점에 따라 중간에 표시될 수 있으므로 그 위치만으로 화면 결함을 단정하지 않았다.
- 실제 WCAG 대비 수치나 보조공학 호환성 인증은 수행하지 않았다.
